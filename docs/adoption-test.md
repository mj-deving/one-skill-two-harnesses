# Adoption test

A fresh agent with no prior knowledge of skillcast followed only the public README to adopt it in a new repo. It was not a person; read the result with that in mind.

- Date: 2026-11-14
- Tester: a Claude Sonnet subagent in Claude Code, briefed only with the README URL and the goal. It was told not to read the source or tests.
- Starting repo: a `CLAUDE.md` with two rules and one Claude Code skill (`release-notes`), no Codex files.
- Goal: Codex files exist, `check` passes, a hand edit to a generated file makes `check` fail, undoing it makes `check` pass again.

## Result

All three goals met in 32 seconds, with no help.

| Step | Command | Exit |
|---|---|---|
| import and build | `npx github:mj-deving/one-skill-two-harnesses init` | 0 |
| build | `npx github:mj-deving/one-skill-two-harnesses build` | 0 ("up to date") |
| check | `npx github:mj-deving/one-skill-two-harnesses check` | 0 |
| hand edit to `AGENTS.md`, then check | same | 1 (`changed AGENTS.md: line 7`) |
| undo, then check | same | 0 |

## README points the tester raised, now fixed

1. The README did not say that `init` also builds, so the `build` after it was a no-op.
2. The README did not say that Cursor rules are generated by default.
3. The tool's messages say `skillcast build`, but no `skillcast` binary exists until the package is on npm.

Before this test, the README told people to run `npx skillcast`, which fails because the package is not on npm. That was found while preparing the test and fixed first.
