# skillcast

Write each agent skill and your project rules once. `skillcast` generates the files Claude Code, Codex and Cursor read, and fails CI when one of them drifts from the source.

Teams that run two coding agents keep the same rules twice (`CLAUDE.md` and `AGENTS.md`, `.claude/skills/` and `.agents/skills/`). The copies drift, and nobody notices until an agent works from stale instructions.

## Five-minute start

```sh
npx github:mj-deving/one-skill-two-harnesses init
npx github:mj-deving/one-skill-two-harnesses build
npx github:mj-deving/one-skill-two-harnesses check   # exit 0: every generated file matches the source
```

This needs Node 20 or newer and nothing else. The package is not on npm yet; the commands run the committed build straight from GitHub.

`init` imports your existing `CLAUDE.md`, `AGENTS.md`, `.claude/skills/*/SKILL.md` and `.agents/skills/*/SKILL.md` into `.skillcast/`. From then on you edit `.skillcast/` only and run `build`.

## Source format

```
.skillcast/
  rules.md              project rules, shared by all harnesses
  skills/<name>.md      one file per skill, frontmatter name + description
```

```markdown
---
name: test-layout
description: "Where and how to write tests. Use when asked to add, write or extend tests."
cursor-globs: "**/*.spec.ts"
---
Shared instructions for every harness.

<!-- only:codex -->
Only Codex sees this line.
<!-- /only -->
```

Harness blocks are `only:claude`, `only:codex` and, in skills, `only:cursor`. Rules have no Cursor block because Cursor reads `AGENTS.md`. Extra frontmatter keys (for example `allowed-tools`) are passed through to both `SKILL.md` files; keys starting with `cursor-` go to Cursor only.

## Generated files per harness

| Harness | Rules | Skills | Format source |
|---|---|---|---|
| Claude Code | `CLAUDE.md` | `.claude/skills/<name>/SKILL.md` | Claude Code skills docs |
| Codex | `AGENTS.md` | `.agents/skills/<name>/SKILL.md` (`name`, `description`) | learn.chatgpt.com/docs/build-skills, read 2026-11-13 |
| Cursor | reads `AGENTS.md` | `.cursor/rules/<name>.mdc` (`description`, `globs`, `alwaysApply`) | cursor.com/docs/context/rules, read 2026-11-13 |

Every generated file carries a comment naming its source. `build` refuses to overwrite a file without that comment, so hand-written files are never lost. Cursor output is generated and covered by golden tests, but it is not measured with real agent runs.

## CI

```yaml
- uses: actions/checkout@v4
- uses: mj-deving/one-skill-two-harnesses@main
```

`check` exits 1 and names the file when a projection is missing, edited by hand, or left over from a deleted skill. `examples/drifted/` contains a hand-edited projection; CI asserts that `check` fails there.

## Migrating an existing repo

Run `init`. If `CLAUDE.md` and `AGENTS.md` differ, or the same skill is described differently in both harnesses, `init` stops, lists the conflicts and writes nothing. Make the originals agree, then run it again.

## Results

Run [`results/2026-11-13T20-37-42`](results/2026-11-13T20-37-42/summary.md): six tasks over three skills, two of them held out, in Claude Code 2.1.319 (claude-opus-5-5) and codex-cli 0.167.0 (gpt-5.6-sol). Each run is scored by a deterministic script, not by a model.

| harness | no skill files | hand-maintained copy | generated by skillcast |
|---|---|---|---|
| Claude Code | 1/6 | 18/18 | 18/18 |
| Codex | 1/6 | 18/18 | 18/18 |

The generated files did exactly as well as the plain copy in both harnesses, and both beat the no-skill control. The one control pass is the held-out changelog task, where the existing CHANGELOG.md already shows the format. Every failure is listed with its reason in the summary.

Limits of this run: both skill variants hit the ceiling, so the bench shows no loss from generation but cannot rank small differences. It ran on one machine with the user's own installed skills present. Cursor output is not measured.

```sh
bun run bench            # all tasks, both harnesses
bun run bench --set=heldout
```

## What it does not do

- It does not judge whether a skill is good, only whether the generated files match the source and still work in each harness.
- It does not host, share or install skills from elsewhere.
- It does not translate harness-specific features such as Claude Code hooks or Codex config.
- It does not isolate the bench from user-level skills or instructions installed on the machine that runs it.
